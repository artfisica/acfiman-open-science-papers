\section{Protocolo propuesto para evaluar futuras sesiones}
Proponemos registrar por separado la preparación realizada por el equipo docente y la incorporación de los estudiantes. El tiempo del instructor incluye diseño, pruebas y mantenimiento. El tiempo de inicio de cada participante debe medirse entre dos eventos observables: por ejemplo, recibir las instrucciones y completar una ejecución de validación. Ambos pueden importar, pero responden preguntas distintas.

Para una cohorte de $N$ participantes previstos, definimos $S$ como quienes completan la validación y $T_i=t_{i,\mathrm{validación}}-t_{i,\mathrm{inicio}}$ para cada caso con medición disponible. Se informarían la proporción $S/N$, mediana y dispersión de $T_i$, junto con fallos y datos ausentes. Si se utiliza un percentil alto para describir la cola de tiempos, debe indicarse el método de cálculo. Estos indicadores se proponen para futuras mediciones; no se calculan aquí a partir de la frase agregada del resumen.

El registro mínimo incluye versión del repositorio, imagen o configuración del entorno, región o servicio utilizado cuando sea relevante, estado de preconstrucción, tamaño de la descarga y categorías de incidencias. Los registros públicos deben ser agregados o anonimizarse de manera adecuada. No se necesita publicar nombres, identificadores de cuentas ni direcciones IP para describir el funcionamiento de una cohorte.

Una comparación con instalación local requiere tareas y condiciones equivalentes, y debe informar diferencias de experiencia previa y conectividad. Una asignación no aleatoria puede producir grupos distintos desde el comienzo. Además, el tiempo ahorrado durante la clase puede corresponder a trabajo desplazado al instructor. Por ello conviene presentar el costo total de preparación y soporte, y no únicamente el momento en que el estudiante abre el navegador.

El aprendizaje exige otra evaluación. Una tarea individual de interpretación, una explicación de un cambio y una reproducción posterior pueden aportar información diferente de un cuestionario de satisfacción. El protocolo debería distinguir habilidad para usar la plataforma, comprensión del procedimiento y razonamiento físico. Que un análisis se ejecute automáticamente no demuestra que el participante pueda explicar sus supuestos.
